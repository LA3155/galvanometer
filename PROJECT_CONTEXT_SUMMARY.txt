一、项目定位与核心卖点（面试一句话总结）
--------------------------------------------------------------------------------
针对智能穿戴设备（智能手表/手环）功耗跨度大（uA 到百 mA）、突发脉冲捕捉难的特点，
基于 GD32F303CGT6 (Cortex-M4F) 打造的便携式功耗分析仪。具备 100Hz 连续高边采样、
三档硬件量程校准、ST7789 帧缓冲无频闪波形显示、状态突变捕获、Flash 环形日志与 USB 数据导出。

面试核心竞争力：
1. 软硬协同能力：完成 PCB 焊接调试与采样硬件链路搭建，实现三档零点 Offset 软件校准。
2. RTOS 实时架构：基于 FreeRTOS 进行 5 任务解耦，100Hz 采样与 20Hz 界面刷新、CDC 导出互不阻塞。
3. 底层驱动攻坚：ST7789 SPI0 DMA 传输（突破全双工 RXORERR 溢出、RGB565 大小端转换、46KB 显存帧缓冲）。
4. 业务算法深度：功耗状态机自动识别（深睡/浅睡/活跃/射频突发）并锁定突变前后瞬态波形。


二、硬件与系统规格
--------------------------------------------------------------------------------
【主控芯片】 GD32F303CGT6（主频 120MHz，96KB SRAM，1MB Flash，开启硬件 FPU）
【功耗采集】 TI INA226（硬件 I2C，地址 0x40，分流电压分辨率 2.5uV，总线电压 1.25mV）
【采样量程】 10mΩ / 1Ω / 10Ω 三档（硬件跳线切换，软件按键切换量程系数与校准值）
【显示屏幕】 ST7789 1.54寸 240x240 LCD（SPI0 接口，DMA 传输，46KB 内部帧缓冲）
【存储芯片】 GD25Q64（8MB SPI NOR Flash，SPI1 接口，扇区擦除 4KB，页写 256B）
【通信接口】 Type-C 接口（USB CDC 虚拟串口，支持 64 字节分包长数据导出）
【按键交互】 4 个独立按键（EXTI 中断 + 消息队列）：
             - KEY1：切换量程档位
             - KEY2：触发当前档位零点校准
             - KEY3：触发屏幕 200 点快照导出
             - KEY4：触发 Flash 全量历史日志导出
【硬件说明】 初版 PCB 未预留标准 USB D+ 上拉控制，飞线后仅稳定支持单向发送至 PC，
             故操作均采用按键触发，不采用双向串口命令行交互。


三、软件架构与已实现功能
--------------------------------------------------------------------------------
1. 代码分层结构：
   - core/  ：系统启动、GPIO、SPI、I2C、DMA、Flash 驱动、FreeRTOS 底层
   - bsp/   ：LCD 屏幕绘图底层、INA226 寄存器读写、按键处理、精准延时
   - app/   ：换算校准(power_sample)、帧缓冲波形(waveform_draw)、状态机(event_detect)、日志存储(log_store)
   - Tasks/ ：FreeRTOS 任务实现（硬件初始化、采样、按键、显示、数据发送）
   - cdc/   ：USB CDC 协议栈与分包数据传输

2. 已完成并验证的功能：
   [已完成] 100Hz 定时采样链路：软件定时器 10ms 释放信号量，周期采集 V/I/P，三档 Offset 校准
   [已完成] ST7789 帧缓冲波形刷新：46KB RAM 帧缓冲 + Bresenham 折线绘制，DMA 整屏推送，彻底无频闪
   [已完成] SPI0 互斥锁保护：osMutexAcquire 保护 LCD SPI0 传输，杜绝多任务并发冲突
   [已完成] 200 点波形快照导出：环形保存最近 2 秒数据与极值，KEY3 触发 CDC 导出 CSV
   [已完成] SPI Flash 底层驱动：调通 JEDEC ID 读取、页写、扇区擦除、连续读
   [已完成] USB CDC 稳定分包：cdc_write 循环切分 64 字节发送，长文本不截断


四、高价值后续攻坚任务（秋招技术深度提升重点）
--------------------------------------------------------------------------------
1. 【核心亮点】Flash 异步环形日志存储优化 (app/log_store.c)
   - 当前问题：写事件时在 100Hz 采样线程内同步擦除 0 扇区（阻塞 50~100ms），破坏采样实时性并磨损 Flash。
   - 改造方案：
     (1) 异步队列：采样任务产生日志事件直接推入队列，由独立的低优先级存储任务后台写入。
     (2) 磨损均衡：废除单扇区高频擦写，采用扇区轮转与元数据追加标记机制。
     (3) 双模式记录：日常 10Hz 低频记录功耗趋势；突变时记录触发前后瞬态波形（Pre/Post 100点）。

2. 【核心亮点】穿戴设备功耗状态机与统计报告 (app/event_detect.c)
   - 当前问题：仅有基础分类，TX 突发未闭环，缺乏实际业务统计输出。
   - 改造方案：
     (1) 细化状态：覆盖深睡(<10uA)、浅睡(<1mA)、待机(1~10mA)、活跃(>10mA)、射频突发(>50mA 持续<50ms)。
     (2) 统计分析：RAM 实时累计各状态时长占比、唤醒次数、平均电流、能耗贡献率。
     (3) 总结报告：导出一段文本摘要（如：运行30分钟，深睡85%，活跃12%，发射3次，平均功耗2.8mW）。

3. 【代码健壮性】已知缺陷与边界保护
   [待修复] waveform_draw.c 中 map_current_to_y_at 限幅时改写了全局原始数组，需改用局部变量。
   [待修复] waveform_draw.c 中 waveform_redraw 循环 i=0 时访问 y_buf[-1] 数组非法越界。
   [待修复] log_store.c 中 log_erase_all 当前只擦除了 64KB，需修正为擦除整片 8MB 数据区。

4. 【加分项】PC 端 Python 可视化分析脚本
   - 编写轻量脚本监听 COM 口，接收 KEY3/KEY4 导出的 CSV 数据。
   - 自动生成功耗曲线并标注事件唤醒与射频脉冲，导出图表报告，面试时直接作为实物作品展示。


五、秋招面试高频提问与话术复盘
--------------------------------------------------------------------------------
Q1: 为什么不用单任务大循环，而要引入 FreeRTOS？
A1: 功耗分析仪要求严格的 100Hz 等间隔采样。如果使用裸机大循环，LCD 刷屏、Flash 擦写（几十毫秒）
    以及 USB 发送都会造成严重的采样丢拍和时钟抖动。引入 FreeRTOS 后，将 100Hz 采样设为高优先级任务，
    通过硬件/定时器信号量唤醒；将 UI 绘制和 CDC 导出放到低优先级后台处理，实现了真正的实时与解耦。

Q2: SPI LCD 驱动遇到了哪些底层挑战？如何解决的？
A2: 主要攻克了三个问题：
    (1) SPI 全双工溢出：只开 TX DMA 时 RX FIFO 容易溢出导致 RXORERR 报错，在传输完成退出时增加了排空 RX 缓冲逻辑；
    (2) 界面频闪：早期边算边发导致屏幕闪烁，利用芯片 96KB SRAM 优势开辟 46KB 显存帧缓冲，在 RAM 中完成
        Bresenham 折线绘制后一次性通过 DMA 推送，实现 20fps 稳定无闪烁显示；
    (3) 大小端转换：Cortex-M 为小端字节序，ST7789 屏幕需要大端 RGB565，采用 GCC 内建函数 __builtin_bswap16
        进行硬件级单周期字节序转换。

Q3: 如何捕获低功耗设备毫秒级的突变事件（如蓝牙广播脉冲）？
A3: 系统维护了一个 50 点的环形缓冲队列（Pre-buffer）。当状态机算法检测到电流急剧上升或斜率超标时，
    判定为触发事件，继续向后抓取 50 点（Post-buffer）。最终将触发前 500ms、瞬态触发点、触发后 500ms
    共 100 点数据完整打包，既节省存储空间，又能高分辨率还原突发事件全貌。
