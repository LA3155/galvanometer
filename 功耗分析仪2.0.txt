〇、改版总览
--------------------------------------------------------------------------------
[必改-1] USB_DP 补 1.5K 上拉电阻 —— 修复 CDC 只能发、不能收命令
[必改-2] 量程切换电子化：跳线帽手动切换 → 按键 + MOS 管自动切换
         （结论先说：加普通三极管不行，要用 N-MOS，分析见第二节）
[必改-3] ESP32-C3-12F 串口从 UART0（GPIO20/21，日志口）改到 UART1（GPIO6/GPIO7，AT 命令口）
         —— 已上网核实，依据见第三节（含勘误：1.0 接线交叉无误，纯属串口选错）
[建议-4] 顺带优化：ESP32 的 UART0 引到测试点、GD32 空闲 IO 分配、
         删除 H1/H2/H3 跳线排针、软件配套改动清单


一、改版点 1：USB_DP 补 1.5K 上拉电阻（必改，修复 CDC 接收）
--------------------------------------------------------------------------------
1.1 故障现象
    - USB CDC 发送数据正常（导出 CSV、波形快照都正常）
    - 上位机发命令给设备收不到（CDC 接收异常）
    - 曾飞线一个 1K 电阻后收发都正常（现已拆除）→ 证实是硬件缺件问题

1.2 根因分析（结合网表）
    网表中 USB_DP 网络：D1.1 / D1.6（ESD）+ R9.1（22Ω 串阻）+ USB2.A6/B6，
    再经 R9 接 U6.33（PA12 = USB DP）。
    全网络没有任何上拉电阻。
    GD32F303 的 USB 全速器件需要在 D+ 上接 1.5K 上拉到 3.3V，向主机宣告
    "全速设备已接入"。缺上拉时主机对设备的枚举/识别不稳定，表现为
    单向通信异常。GD32F303 芯片内部没有集成该上拉（同 STM32F103），必须外部贴。

1.3 修改方案
    - 新增 1 颗 0402 电阻 R21（位号顺延）：1.5K
    - 连接：PA12 网络（即 R9.2 与 U6.33 之间的节点）—— 上拉到 3V3_SYS
      （放在 22Ω 串阻内侧、靠 MCU 一侧）
    - 标准值就是 1.5K（1/16W 精度无需高，5% 即可）
    - 可选进阶（不强制）：上拉经一颗 N-MOS（AO3400）由空闲 GPIO 控制通断，
      可实现 USB 软断开/重新枚举，方便调试时复位 USB。最简方案固定上拉即可。

1.4 验收标准
    插 USB 后设备管理器稳定识别 CDC 串口，无重插/掉设备现象；
    上位机下发命令（如启动导出）设备能正确响应。


二、改版点 2：量程切换电子化（手动跳线 → 按键控制 MOS 切换）
--------------------------------------------------------------------------------
2.1 现状拓扑还原（网表分析结果）
    电流主路径：5V_IN → U1(P-MOS 高边开关, GD32_DUT_EN 控制) → DUT_SRC
                → 三档采样电阻高端并联（U2=10mΩ / U3=1Ω / U4=10Ω，2512）
                → 各自低端独立引出 RSH_10m_L / RSH_1R_L / RSH_10R_L
    量程选择：
      H3 排针插帽：把选定档电阻低端接到 DUT_OUT_P（电流路径）
      H2 排针插帽：把选定档电阻低端接到 INA_INN（测量路径）
      H1 排针插帽：把 DUT_SRC 接到 INA_INP（IN+ 固定接电阻高端）
    测量：INA226(U5) 差分测量 IN+ 与 IN- 之间（即选定采样电阻两端）压降
    输出：DUT_OUT_P → USB4 座 VBUS 给被测设备供电

2.2 "加三极管就好了？"——不行，直接说结论
    普通三极管（BJT）：导通时 Vce(sat) 有 0.1~0.3V 饱和压降且随温度漂移，
      相当于串联了一个几十~几百 Ω 且不稳定的"电阻"：
      - 10mΩ 档：直接报废（压降比采样电阻本身大上千倍）
      - 1Ω 档：引入 10% 级误差且温漂不可校准
      ❌ 不可用
    继电器：信号继电器触点电阻典型 50~100mΩ，比 MOS 大一个数量级，
      体积/功耗/成本都差，同样毁掉 10mΩ 档。❌ 不推荐
    N-MOS 管：导通本质是毫欧级线性电阻（Rds(on)），串联进回路后可被
      软件三档系数校准吸收，是正确选择。✅ 推荐

2.3 推荐方案：三档并联 + 每档一颗 N-MOS 低边开关
    （沿用现有"三电阻并联"拓扑，仅把 H2/H3 的跳线帽换成 MOS，PCB 改动最小）

     DUT_SRC ──┬──[U2 10mΩ]──┬────────────────────┐
               │              │Q_A(N-MOS)          │
               ├──[U3 1Ω  ]──┼──[Q_B]──┐          │
               │              │        │          │
               └──[U4 10Ω ]──┴──[Q_C]──┼── DUT_OUT_P ── USB4(VBUS) → 被测设备
                                        │
     INA226 IN+ (INA_INP) ── DUT_SRC ───┤   ※ IN+/IN- 改为固定连接！
     INA226 IN- (INA_INN) ── DUT_OUT_P ─┘   不再需要 H1/H2 选择测量点

    关键发现（本次分析的核心简化）：
      INA_INN 不需要逐档切换！只要固定接 DUT_OUT_P 母线：
      压差 = V(DUT_SRC) - V(DUT_OUT_P) = "当前导通档电阻 + 该档 MOS Rds(on)"
      未导通档的电阻低端悬空、无电流流过，不影响测量。
      因此 H1/H2/H3 三排跳线全部删除，测量路径零改动，只加 3 颗 MOS。
      （模拟开关方案被否掉的原因：INA_INN 逐档切换需要模拟开关，但
        DUT_OUT 电压可达 5V，3.3V 供电的模拟开关会削波；改 5V 供电又有
        逻辑电平问题。固定接法从根上回避了这个问题。）

2.4 器件选型
    Q_A（10mΩ 档，误差最敏感）：
      首选超低 Rds(on) 双 N-MOS，如 SISS82DN（两管并联用，合计约 2.4mΩ）；
      或低成本方案：2 颗 AO3400A 并联（约 15mΩ，总阻 25mΩ，
      温漂约 0.4%/℃×15mΩ，自热可忽略，校准后 1% 级精度可保）
    Q_B（1Ω 档）/ Q_C（10Ω 档）：AO3400A 单颗（Rds(on) 约 28mΩ@Vgs=2.5V）
      1Ω+0.028=1.028Ω、10Ω+0.028=10.028Ω，误差 2.7%/0.3%，三档独立
      系数校准直接吸收（现有软件本来就是三档独立换算+独立零点校准）
    栅极驱动：GD32 GPIO 3.3V 直推，必须选逻辑电平管（Vgs(th) < 1V）
    每颗 MOS 栅极配 100K 下拉到 GND：上电/复位/烧录期间默认全关断，
      DUT 回路断开（安全默认态），初始化完成后再由软件选档

2.5 GD32 空闲 IO 分配（网表核对，LQFP48 尚有 8 脚未用）
    空闲：U6.18(PB0)、U6.19(PB1)、U6.21(PB10)、U6.22(PB11)、
          U6.29(PA8)、U6.30(PA9)、U6.31(PA10)、U6.45(PB8)
    建议分配：
      PB0  (U6.18) → RANGE_EN_10M   10mΩ 档 MOS 栅极
      PB1  (U6.19) → RANGE_EN_1R    1Ω   档 MOS 栅极
      PB10 (U6.21) → RANGE_EN_10R   10Ω  档 MOS 栅极
    （3 根独热控制，软件保证同一时刻仅 1 路有效）

2.6 功率与量程核算（复核）
    10mΩ 档：上限受 INA226 分流电压 ±81.92mV 限制 ≈ 1.5A 量级（安全）
    1Ω 档：  81.92mV / 1.028Ω ≈ 79mA
    10Ω 档： 81.92mV / 10.028Ω ≈ 8mA
    各档功耗均在 mW 级，2512 与 SOT-23 均无压力。

2.7 切换时序（软件配套，防炸管/防 DUT 掉电）
    - 互锁：任何时刻只允许 1 路使能（若两档并联，大电流会全走小电阻档，
      例如 10mΩ 与 10Ω 并联时 500mA 几乎全灌 10Ω 档 → 2.5W 烧毁）
    - 切换采用"先断后合"，两步之间空窗控制在 1ms 以内，
      被测设备输入电容（通常 ≥1uF）足以撑住不掉电重启
    - 上电默认档：建议 10mΩ 档（最大量程，最安全），或恢复掉电前档位
    - KEY1 现有功能保留：由"切换软件系数"升级为"系数+硬件 MOS 同步切换"

2.8 备选方案：阶梯电阻法（仅记录，不推荐首选）
    DUT_SRC—10mΩ—A—1Ω—B—10Ω—C(=DUT_OUT)，加 2 个旁路 MOS：
    K1 短接 A→OUT 选 10mΩ 档；K2 短接 B→OUT 选 1.01Ω 档；全断=11.01Ω 档。
    优点：只省 1 颗 MOS；缺点：阻值叠加、系数表要重标、1Ω/10Ω 档电流
    也流过前级电阻。与现有 PCB 拓扑差异大，不采用。

2.9 验收标准
    按键循环切换三档，LCD 档位显示与实际导通档一致；
    万用表测各档总阻值（含 MOS）与系数表一致；
    带载切换（如 100mA 负载下 10mΩ↔1Ω 来回切）DUT 不重启、不炸管。


三、改版点 3：ESP32-C3-12F 串口改用 UART1（GPIO7/GPIO6）
--------------------------------------------------------------------------------
3.1 故障现象与根因（v1.1 勘误修订）
    当前无法使用 ESP32-C3-12F。
    网表现状（引脚映射按实际模组原理图核对，初版有误已更正）：
      'USART1_TX'（GD32 PA2, U6.12）→ L1.21 = 模组 Pin21 = GPIO20 = U0RXD（RX）
      'USART1_RX'（GD32 PA3, U6.13）→ L1.22 = 模组 Pin22 = GPIO21 = U0TXD（TX）
      即 TX→RX / RX→TX 交叉互连，接线本身完全正确。
      【勘误】初版曾误判为"TX-TX 同名直连"，系把模组引脚号错当成
      GPIO 号（想当然认为 Pin21=GPIO21）所致，特此更正。
    根因：不是接线错，是串口选错——接到了 UART0（日志口）。
      ESP32-C3 的 GPIO20/21 是 UART0，AT 固件将其固定用作固件下载口 +
      日志输出口：模组上电 bootloader 与运行期日志全部从 U0TXD(GPIO21)
      吐出（GD32 的 PA3 收到的就是日志），而 AT 命令收发通道在 UART1
      （IO6/IO7）上，发到 U0RXD(GPIO20) 的 AT 命令固件不解析。
      表现为：能收到日志、AT 无响应，即"无法使用"。

3.2 上网核实结论（2026-09-09 查证）
    乐鑫官方 ESP-AT 文档（ESP32-C3 系列）明确：
      UART0：下载固件 + 输出日志   TX=GPIO21，RX=GPIO20
      UART1：发送 AT 命令 / 接收 AT 响应（及自定义数据收发）
             TX=GPIO7，RX=GPIO6（出厂 AT 固件默认，定义在
             factory_param_data.csv 的 uart_tx_pin/uart_rx_pin）
    → 用户说法"UART1 发送(TX)=GPIO7，UART1 接收(RX)=GPIO6"完全正确 ✅

3.3 修改方案（引脚级）
    改版目标：GD32 串口从 UART0（日志口）挪到 UART1（AT 命令口），TX/RX 交叉：
      GD32 PA2 (USART1_TX, U6.12) → 模组 IO6（UART1 RX）
      GD32 PA3 (USART1_RX, U6.13) ← 模组 IO7（UART1 TX）
    ⚠ 具体焊盘号以你手上这颗信路达(WIRELM) ESP-C3-12F 为准：
      你的原理图符号已标注 21=RX、22=TX，在同一符号上直接查 IO6/IO7
      对应的引脚号即可（嘉立创元件库符号与实物封装一一对应）。
      注意：安信可版 ESP-C3-12F 的 IO6/IO7 在 Pin12/Pin13，但信路达版
      引脚分布不同（EN 在 Pin3、RX/TX 在 Pin21/22），不能套用，务必以
      自己的符号/规格书为准。
    两端均为 3.3V 系统，直连即可（无需电平转换）。

3.4 顺带建议（强烈建议，成本几乎为零）
    a) 把模组的 UART0（Pin21=RX / Pin22=TX）引到 2 个测试点（ESP_RXD0 / ESP_TXD0），
       以后给 ESP32 刷 AT 固件、抓启动日志都不用拆板飞线。
    b) 再引 2 个测试点：EN（Pin3，对地短接一下即复位 ESP32）和
       IO9/BOOT（R16/R17 两颗 10K 上拉之一，符号上确认哪脚是 IO9；
       进下载模式 = IO9 拉低的同时复位）。凑齐 4 个测试点即可免拆板
       给 ESP32 刷固件（后续 MQTT 上云大概率要用）。
    （ESP32-C3 若自刷 ESP-IDF 固件，UART1 引脚可经 GPIO matrix 重映射，
      但按 AT 固件默认 GPIO6/7 走最省事，也避免换固件又要改板。）

3.5 验收标准
    上电后 GD32 通过 USART1 向 GPIO6 发 "AT\r\n"，能从 GPIO7 收到 "OK"；
    模组上电/复位瞬间 GD32 串口不再收到乱码日志。


四、软件配套改动汇总（硬件改完后需要动的代码）
--------------------------------------------------------------------------------
1. 量程模块（power_sample / KEY1 流程）：
   - KEY1 档位切换由"纯软件系数切换"升级为"GPIO 切 MOS + 系数切换"原子操作
   - 三档换算系数改为实测总阻值（采样电阻 + MOS Rds(on)），保留三档独立
     Offset 零点校准（KEY2 逻辑不变）
   - 新增互锁与先断后合时序（空窗 <1ms）；上电默认 10mΩ 档
2. ESP32 模块（bsp ESP32 串口）：
   - USART1 PA2/PA3 配置不变，仅接线对象变化，协议按 AT 固件 115200 8N1
   - 后续 MQTT 上云（攻坚任务 #2）即走此通道
3. USB CDC：无软件改动，硬件补上拉即恢复。


五、网表勘误与其他备注（1.0 版备查）
--------------------------------------------------------------------------------
1. U6.44(PB2/BOOT1) 经 R12 10K 下拉、U6.20(BOOT0) 经 R11 10K 下拉 —— 正常。
2. Q1 基极直连 U6.46(PB9=GD32_DUT_EN) 未串限流电阻（仅 R6 10K 下拉），
   功能正常但不规范，2.0 版顺手加 1K~4.7K 串阻更稳（可选）。
3. INA226(U5) 地址 0x40、I2C 上拉 R7/R8 4.7K —— 不变。
4. H1/H2/H3、EXT_DUT_IN(H4/H6) 跳线排针：H1/H2/H3 删除（被 MOS 方案取代），
   H4/H6（DUT 供电来源选择：板载 3.3V LDO / 外部输入）保留不动。
5. 改版后建议在 DUT_SRC / DUT_OUT_P / 三档电阻低端各留 1 个测试点，
   方便后续校准和 debug。
